📋 Field Guide

SYNTAX ERROR

Python can't even parse the code — it's caught before the program runs at all. Missing colons, unmatched brackets, misspelled keywords.

RUNTIME ERROR

The code is valid and starts running, then crashes partway through because of what happens with a specific input. Shows up as a named error like IndexError or ValueError.

LOGIC ERROR

The code runs from start to finish with no crash and no error message — it just produces the wrong answer.

HEALTHY

Runs correctly with no crash and the right output. Not every patient is sick — knowing when there's no error is its own skill.

TYPICAL CASE TEST

Ordinary, expected input — the kind of input the program will see most often.

BOUNDARY CASE TEST

Input right at the edge of what's valid — an empty list, the first/last index, a minimum or maximum allowed value.

EDGE CASE TEST

Unusual but still valid input that stresses the logic without being at a strict boundary — all-negative numbers, duplicates, a huge or oddly-shaped input.

INVALID / EXCEPTION-INPUT TEST

Input the program should reject or handle carefully — wrong data type, out-of-range value, malformed text.

N/A — WON'T RUN TO TEST

Syntax errors are caught before any code executes, so no test case can "run into" them — testing doesn't apply the same way.
